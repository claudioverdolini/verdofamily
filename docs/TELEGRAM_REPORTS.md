# Telegram automatic reports

VerdoFamily can send scheduled family reports through a Telegram bot.

## Runtime components

- Supabase Edge Function: `telegram-reports`
- Database migration: `20260916102000_telegram_automatic_reports.sql`
- Scheduler: `pg_cron` job `verdofamily_telegram_reports_minutely` (every minute)
- Telegram delivery uses long polling (`getUpdates`), so no public Telegram webhook is required.
- Each VerdoFamily cloud user links their own private Telegram chat through a short-lived deep-link token.

## Required secret

Set this only in Supabase Edge Function Secrets, never in Git:

- `TELEGRAM_BOT_TOKEN` — token generated by Telegram `@BotFather`

The cron authentication secret is generated automatically in the service-only `telegram_bot_state` table by the migration.

## Data tables

- `telegram_connections` — VerdoFamily user ↔ Telegram private chat mapping
- `telegram_link_tokens` — short-lived one-time linking tokens
- `report_schedules` — per-user schedules and report section preferences
- `report_delivery_logs` — delivery/deduplication history
- `telegram_bot_state` — bot polling offset and private cron secret

All of these tables have RLS enabled and browser roles have no direct grants. Browser requests go through the Edge Function, which verifies the Supabase JWT and family membership.

## Privacy defaults

Health data is excluded from Telegram reports by default. A user must explicitly enable `include_health` on an individual report schedule before health-related calendar/deadline items can leave VerdoFamily.

## Recovery

1. Recreate Supabase and apply repository migrations in order.
2. Deploy `supabase/functions/telegram-reports/index.ts` with JWT verification disabled because the function performs custom JWT/cron authentication internally.
3. Re-add `TELEGRAM_BOT_TOKEN` to Supabase Edge Function Secrets.
4. Verify the `verdofamily_telegram_reports_minutely` cron job is active.
5. Users can reconnect Telegram from VerdoFamily settings if chat mappings are not present in the restored database.
